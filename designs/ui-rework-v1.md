## 0. 一句话总纲

**做成一个聊天产品，不是一个仪表盘。** 核心对象=对话：用户永远在对话里，或在去对话的路上；一切实现细节（三连接、订阅、写通道）退到后台。

## 1. 竞品范式对照（设计依据）

| 环节 | 现状（零件堆叠） | 目标范式（ChatGPT/Claude/LibreChat 通行） |
|---|---|---|
| 新建会话 | 表单：选模型→填首条消息→点「创建会话」 | **直接开聊**：新对话页=输入框+模型下拉；首条消息发出即建会话（autoFile 链已有） |
| 连接状态 | 常驻三格「列表/订阅/写」 | **全局健康点**（顶栏角落小圆点）：绿=全通、黄=部分断（自动重连中）、红=全断；点开才见细节 |
| 会话列表 | 平铺一串 | **时间分组**：今天/昨天/前 7 天/更早（lastActiveMs 已有）；组头 sticky |
| 模型选择 | 只在新建表单里 | **对话页顶部下拉**随时切；记住上次（LAST_MODEL_KEY 已有）；下一条消息生效 |
| 手机端 | 列表+对话上下挤一屏（40vh/60vh） | **两视图切换**：列表视图↔对话视图（<768px）；点会话/新建进对话，左上返回；桌面恒双栏 |
| 空态 | 一行字「选择会话开始」 | **中央大输入框**直接可打字（输入即新对话）+「或从下面会话继续」 |

## 2. 组件面变更

### 2.1 退役
- `NewSession` 表单组件（整面死）——首条消息链改走新对话态。
- `connbar` 三格状态条（real-app）。

### 2.2 新增/重排
- **`HealthDot`**（顶栏角落）：聚合三客户端状态→三档。自动重连状态挂黄点点缀（转圈/文案 tooltip）。认证失败仍走独立受控面（不变）。
- **`EmptyConversation`**（新对话态）：仅含对话头（「新对话」+模型下拉）+composer。首条 sendPrompt（write-client 已有 launched→file 回调）→切到会话详情。
- **`Sidebar`**：顶部「＋ 新对话」大按钮（整行）→时间分组列表（`SessionList` 改造：分组渲染，条目=标题+相对时间）。
- **`ConversationHeader`**：返回钮（仅手机）+标题+模型下拉（读清单+记住上次；会话中切换=下条生效，不重发不提醒服务端）。
- **`Welcome`**（空态）：中央大 composer（复用 EmptyConversation 的输入面）+继续会话引导。
- **real-app 重排**：topbar（品牌+HealthDot+ThemeToggle）→ workspace（sidebar+main）。手机态 workspace 单子渲染：view∈{list,conversation}，选中会话/新建→conversation，返回→list。

### 2.3 保持零改动
- ws/subscribe/write 三客户端协议、帧、服务端全部代码。**本批纯前端。**
- 自动重连壳层（体验收敛批落地）原样保留，只换呈现面。

## 3. 交互细则（易错点先定）

1. **新对话流程**：点「＋ 新对话」或空态输入→main 切 EmptyConversation→用户打字→send({text, model})→write-ack/launched→file 确定→main 切 SessionDetail（订阅开始）→sidebar 列表刷新（已有 dirty 合并）。**取消**（手机返回）=丢弃草稿回列表，无确认弹窗（减法哲学）。
2. **模型下拉**：数据=get-models 清单（M-OPS 已有）+「默认（pi 配置）」+手输自定义（保留直达，清单失败时兜底）。切换只改本地待发值；会话运行中切换不中断当前 turn。
3. **分组边界**：今天=本地 0 点起；昨天=前一个自然日；前 7 天；更早。空组不渲染。lastActiveMs=null 归「更早」。
4. **健康点聚合**：三连接 ready=绿；任一 closed/error 且自动重连在跑=黄；三面全断=红。点黄/红→浮层显示三面明细+「立即重连」钮。认证失败不进健康点（独立受控面不变）。
5. **手机视图状态**：view 由 UI 层 state 持有（不进 URL——会话选择已由 file state 持有，同层）。断线重连不重置 view。
6. **桌面空态 vs 新对话态**：桌面初始=file=null 显 Welcome（含大输入框）；点输入框/「＋ 新对话」→EmptyConversation。两者区别仅 header 文案（「开始」vs「新对话」），输入面同体。

## 3.5 键盘可达性

- composer：Enter 发送/Shift+Enter 换行（现有 write-composer 语义保留）。
- 列表条目=button（现有）；分组头=非交互 heading。
- HealthDot=button（aria-label=状态文案）；浮层 Esc 关。

## 4. 测试面策略

- **重写**：real-app.test（布局/两视图/健康点聚合/新对话全链）、new-session.test→empty-conversation.test（首条消息=建会话+模型随发）、mux-b1/b2 中 NewSession 相关例迁移改造。
- **保留**：ws-client/subscribe/write-client 单元面全保（协议零动）；自动重连三例全保（呈现面断言改 HealthDot）。
- **新增杀点**：模型下拉切换后首条消息帧携带新 model；两视图切换 file 不丢；分组归属日界计算。

## 5. 施工切批（GPT-6.1-sol:high 主写；每批可独立验收）

- **批 R1（骨架）**：topbar+HealthDot（connbar 退役）+Sidebar 分组+手机两视图+新对话流程（NewSession 表单退役）。验收=六范式全落地，全仓绿+无头 390/1280 截图过 looker。
- **批 R2（打磨）**：对话头模型下拉+Welcome 大输入框+视觉细化（间距/暗色/动效 reduced-motion 同步）。
- **批 R3（滚动，可选）**：列表条目摘要预览、健康点浮层明细等增强——按用户验收反馈定。

## 6. 验收门

- 每批：全量测试绿+tsc 0+变异杀点（改必杀）+无头浏览器（390/1280/暗色）looker 审+交叉审≥85（R1/R2 Kimi 或 DS-flash）。
- 终态：用户手机+桌面实测验收。

## 7. 风险与边界

- **测试迁移量大**（new-session/mux 系列多例围绕表单写）——迁移即重写，不许假绿。
- **autoFile 首链回归风险**——批 R1 必含「新建→发消息→会话出现」E2E 级例（假 socket 全链已有先例）。
- **历史会话贯通不在本批**（单层裸名 vs 子目录树=契约+安全面，另行设计门）——本批列表仍只显当前授权根。
- 服务端零改动=回滚面小（dist 回滚即回退）。
