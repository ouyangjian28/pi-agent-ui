# 混合核心 UI · 第一版可点击样板

## 怎么看

打开同目录 `index.html` 即可，不需要启动服务器或安装依赖；JS/CSS 已内联，无远程资源。可在文件卡片里预览，或下载后用浏览器打开。顶部一直标注“模拟数据”，不会调用模型、读写日常会话或切换服务。

先试这条路：**新建 → 发一条演示消息 → 切换到别的会话 → 回来继续**。再展开一张工具过程卡，切换深浅色，缩窄窗口看看手机布局。每个会话有自己的草稿和演示状态；发送与停止只是模拟，不要拿回复判断模型能力。

## 这一版在确认什么

- 整体是 OpenChamber 方向的清晰侧栏/工作区/居中阅读区域，不再沿旧 Codex/VSCode 摆位。
- 聊天内借鉴 pi-web-ui 的过程卡与流式状态：正文是主角，过程默认收起，可展开看摘要和工具活动。
- 手机单列聊天与单独会话列表，输入区保留在视口内；常用控件至少 44px 高。
- 草稿/演示运行状态不串会话。流式演示在接近底部时跟随，手动上翻后不强拽回底部。
- 不照搬别人的执行引擎，也不展示没有后端事实的终端/权限/额度等假入口。

## 已验证与未验证

初版浏览器交互检查通过：草稿保留、新建空会话、演示发送停止、状态归属、手机列表隐藏主面、深浅色、无横向溢出、输入区在实际视口、零 HTTP/提供商请求、无 page exception。补 44px 点击区/流式跟随后最终复检通过；加入完整 React MIT 许可的可重放构建脚本后，又对最终 HTML 重跑截图和交互检查通过。最终证据为本目录 `checks.json` 与 7 张实际视口截图，不把旧图算新代码证明。

截图使用 desktop 1440×900、mobile 390×844、short viewport 390×560，均 `fullPage=false`。短视口**不是真机键盘**。`tests/browser/ui-hybrid-preview.mjs` 可重放检查；这里的测试对象是这个离线样板，不是 RealApp，也不是 SDK 业务接线。

pi 0.99.2 独立候选另已通过 1876 默认回归、构建、三个包类型检查与隔离受控 RPC；原有 24 项真实模型 opt-in 未启用。根 tsc 仍有 111 项历史数量诊断，未宣称根全绿。样板没有改原 RealApp 或冻结协议，日常服务仍原样。
