## 1. 总纲与竞品范式（v2 原文保留）

**做成一个聊天产品，不是一个仪表盘。** 核心对象=对话。且比 v1 多一层：**主读面必须是消息，不是事件日志**（P1-07）；一切实现细节退到后台，但业务失败/未知结果/待答**不可消失**（安全可见性优先于整洁）。

| 环节 | 现状 | 目标范式（ChatGPT/Claude/LibreChat 2026-10 通行结构，范式参照非像素复刻） |
|---|---|---|
| 新建会话 | 表单 | 直接开聊：新对话=输入框+模型待发配置；首条消息发出即建会话 |
| 连接状态 | 三格常驻 | 全局健康点三档+点开明细（唯一恢复入口，R1 必需） |
| 会话列表 | 平铺 | 时间四分组+「加载更多」续页（不做假完整列表） |
| 模型 | 只在新建表单 | 新建时选待发模型；已有会话不显示假当前模型，给「换模型开新对话」入口（契约：运行中会话 model 仅下次冷启动生效） |
| 手机端 | 上下挤一屏 | 两视图切换，业务订阅与可见性解耦 |
| 空态 | 一行字 | 中央大输入框=新对话编辑器本体 |

## 2. 组件面

### 2.1 退役（v2 原文）
- `NewSession` 表单壳（autoFile/readLastModel/writeLastModel/isPersistableModel/__ 哨兵守卫全部抽出保留）
- `connbar` 三格（被 HealthDot 替代）

### 2.2 新增（v2 原文）
- **`HealthDot`**：三档聚合——认证受控面优先；三面全 ready=绿；三面全终态 down（且无在途重连）=红；其余（初连/握手/部分断/退避等待）=黄+文本。点开浮层=三面明细+立即重连；绿可点开；Esc/外点关闭+焦点归还；无纯颜色判断。
- **`EmptyConversation`**：Welcome 与本组件合并为同一受控编辑器（聚焦≠新 draft；首字符/IME/待发模型完整带过首链）；桌面空态与新建态仅 header 文案差异。
- **`ConversationHeader`**：返回钮（手机）+标题+「换模型开新对话」入口；loading/error/empty/streaming 全状态常驻；标题同源 resolveTitle。
- **`Sidebar`**：「＋新对话」+分组列表+续页。

### 2.3 生命周期与状态归属（v2 原文+R2-01 强化）
订阅、业务操作、可见页=三套生命周期。state 归属 RealApp 层：view、活动 file、draftId、草稿（autoFile+文本版本+模型待发值+发起 client 身份）、重连壳层状态。不放重连会卸载的分支。活动会话订阅控制器与可见页解耦（§2.4）。**转移规则见 §3.1。**

### 2.4 订阅保活（v2 原文+R2-07 增补）
- 手机返回列表/断点 767↔768：仅切可见性，不卸载订阅 owner，零 unsubscribe/stop/ui-answer 帧。
- 真换 file（选另一会话/进新对话）：旧订阅退出；旧会话有待答 ui-request 时显式提示，不得沉默取消。
- 隐藏页面不可聚焦（inert）。
- **composer 节点稳定**（R2-07）：同 file 导航/断点切换不卸载 composer——呈现层可换，composer 槽（含 IME 组合/selection/焦点）保持存活；组合期不做可见性切换导致的重挂。
- `useSessionDetail` 现有 cleanup 保留真换 client/file 的退旧清理与提交期 file 身份门；**仅更换 owner 归属**——呈现层不得另挂第二套订阅 effect。

### 2.5 主读面分层（v2 原文+R2-03 交接判据）
- 默认读面=你/助手消息；turn-enqueued/sending/判决/工具入二级「活动详情」区（摘要+展开复用 EntryFrame 通道）；intentId/generation 手输恢复框移入高级诊断折叠。
- **直播→历史交接规则**（R2-03，禁止遇任意 assistant 历史行清当前缓冲——现 live-stream.tsx 行为废除）：
  1. **轮界证据**（新 agent_start/turn_start 到达）：旧轮直播缓冲冻结为「待确认正文」；该轮历史行或 message-final 到达→以历史/final 替换冻结正文（历史=权威），只显示一次。
  2. **同轮内**：final 先到→正文定格，历史行迟到不再重复渲染（存在性核对：同轮已有定格则跳过）；历史行先到→以历史渲染并标记已确认，final 迟到跳过。
  3. **世代隔离**：换 file/订阅重建/client 重建→直播缓冲清空，零串话。
  4. **证据不足分支**（无法判定轮属/对应关系）：保守显示一次直播正文，不猜去重不猜清除；不偷加服务端 ID 字段、不做文本相同性匹配。诚实适用范围：此情形下不宣称全域无条件去重。
- 安全/未知结果/待答提示保留可见；不发明新消息协议；无稳定配对证据不猜配对、不删事件。

### 2.6 列表续页（v2 原文+R2-05 语义固化）
- 基于现有 offset/limit 帧；**nextOffset=回帧 offset+回帧 sessions.length**（非请求 limit，非去重后累计 N；服务端可因字节预算退末条，短页 hasMore=true 不跳项）。
- 累计去重（file 键）+稳定排序（lastActiveMs desc+file 次键）；**去重计数与游标分域**（重复条目不回退游标）。
- listVersion 变化→丢旧页 offset=0 重拉；显式刷新/换 client=**新请求世代**，旧页迟到不并入（即使 listVersion 恰同）；新版本失败可重拉首页。
- 显示「已载 N/共 M」部分载入事实；失败可重试；弱一致即可（不要求服务端快照 token）。

### 2.7 空态文案（v2 原文）
桌面=「从左侧继续或直接开始新对话」；手机列表页=「点会话继续」。

## 3. 状态与交互细则

### 3.1 页面状态与事件转移表（R2-01 重写）

主态：`list | draft(D) | session(file)`；叠加：`editing | sending | rejected | unknown`。
草稿对象：`{draftId, autoFile(稳定), textVersion, model(待发), clientId}`。autoFile 草稿创建时即定；重试同份不换 file，新建下一份才换。

**三门分离**：
1. **记账门**（事实层）：launched=「A 已受理」的既成事实，记入 A 的状态；不因后续文本编辑/导航被遗忘或否定。
2. **导航门**（意图层）：仅当前页面意图仍指向该 draft/session 时才自动切页；**显式返回后迟到回执不得抢页**（留在 list，仅刷新列表出新行）。
3. **清稿门**（身份层）：三元身份（client×file/draftId×文本版本）匹配才清「本次已发送版本」；编辑出的新版本永不清。

**在途编辑策略（owner 拍板）**：允许发送中继续编辑；launched 时清已发送版本，**残稿（新版本）带入 A 的后续 composer**；A 的模型待发语义同时收起（后续消息无「待发模型」假象）。

**事件转移表**：

| 当前态 | 事件 | 下一态 | 活动 file | 订阅动作 | 草稿归属 | 列表刷新 |
|---|---|---|---|---|---|---|
| list | 点「＋新对话」/空态输入 | draft(D) 新建 | — | 不变 | 新 D：autoFile 生成、text=空、model=上次偏好 | — |
| draft(D) editing | 发送（v1） | draft+sending | — | 不变 | 已发版本 v1 记账；composer 开放编辑 | — |
| draft+sending | 编辑文本→v2 | 不变 | — | 不变 | v2 残稿保留 | — |
| draft+sending | launched（意图=D×版本 v1） | session(A) | A | 订 A | 清 v1；残稿 v2 带 A composer；待发模型语义收起 | ✓ 新行 |
| draft+sending | launched（版本失配：v2 在编） | session(A) | A | 订 A | 清 v1 留 v2（带入） | ✓ |
| draft+sending | launched（意图失配：已显式返回 list） | **list 不变（不抢页）** | A（记账） | owner 订 A | 清 v1；v2 残稿留存（再进 A 可见） | ✓ 新行 |
| draft+sending | 明确拒收（§3.2 拒收域） | draft+rejected | — | 不变 | 全文+模型保留 | — |
| draft+sending | 未知（§3.2 未知域） | draft+unknown | — | 不变 | 保留+操作身份留存 | — |
| draft+sending | 发送中点「＋新对话」 | 阻止（提示在途）或完成后再建——**拍板：阻止入口**（在途期间新建按钮禁用+提示），避免双在途 | — | — | — | — |
| draft（未发） | 取消/返回 | list | — | 不变 | 草稿丢弃（无确认，减法） | — |
| session(A) | 手机返回/断点切 | view=list（file 仍 A） | A | **保活**（零退订） | 保留 | — |
| list(file A) | 点 A 重开 | view=conversation | A | 已订 | — | — |
| session(A)/list(file A) | 点会话 B | session(B) | B | 退 A（A 有待答→显式提示） | 下一份新 draft 才有 | — |
| session(A) | 点「＋新对话」 | draft(D2) | A 退订（同换 file 规则；待答提示） | A 退 | D2 新建 | — |
| 任意 | client 替换（重连重建） | 态不变 | — | 重建订阅 | 操作身份换新 client；**在途效果=未知留存**（§3.2） | ✓ |
| 任意 | 重连完成 | view/file/未发草稿全部保留 | — | — | — | ✓ |

迟到回执通则：任何回执先过导航门（当前意图）再过清稿门（三元身份）；旧回执可触发列表刷新，不得把 B 会话/新草稿抢回 A。

### 3.2 发送结果语义（R2-02 穷尽重写）

| 域 | outcome | 语义 | 清稿 | 出口 |
|---|---|---|---|---|
| 服务端 DTO | launched | 已受理/已启动 | 三元匹配才清（§3.1 清稿门） | 进详情/列表刷新 |
| | busy / gate-rejected / identity-rejected | 明确未启动 | 保留全文+模型 | 显式重试/改配置 |
| | not-ready | 明确未启动（进程不就绪） | 保留 | 等就绪重试；**选「默认」重试≠清 sidecar**（X 仍在 sidecar 生效——保留现诚实提示，B3-5 迁移） |
| | no-process | 明确未启动（无进程，如已 settled） | 保留 | 显式重试（将重启进程） |
| | invalidated | 明确拒收（stdin 写前阶段失败） | 保留 | 重试 |
| | gate-failed | 阶段型失败 | **保守未知** | 未知流程（下域） |
| 本地零帧拒绝 | 超长/local-invalid/not-ready/closed | 未发帧，确定零副作用 | 保留（可编辑） | 改输入/重连后重试 |
| | in-flight（同 file×prompt 在途拦截） | 重复拦截 | 保留 | 查看在途请求/等回执 |
| 已发后 | 传输失败/连接终局/长期无回执/UI 等待截止 | **未知**（可能已受理） | 保留+操作身份留存 | 提示未知+可查看目标会话/刷新；**显式二次发送**须：①用户明确确认+重复风险文案 ②解除本地 in-flight 槽（重建 client 或前端在途管理显式清槽+新操作身份） ③禁自动补发/自动换 file |

- UI 等待截止=仅结束「等待中」显示，**不伪造协议失败/取消**。
- hook 返回结构化 outcome（前端内部类型，零帧变更）；`use-write.ts:163` 任意合法 ack→true 的吞稿链废除。
- 首条与后续消息语义一致；prompt 与 stop 并行、停止仅显式触发——保持现语义。

### 3.3 导航与待答（v2 原文）
见 §2.4/§3.1。桌面取消路径同规则（换 file 有待答→提示；同 file 切 view→保活）。

### 3.4 健康点聚合表（v2 原文）

| 条件 | 档位 | 文本 |
|---|---|---|
| 任一面 authFailed/token/跨源拒绝 | 受控面（不自动重连，安全门保持） | 认证失败/需重新进入 |
| 三面全 ready | 绿 | 已连接 |
| 三面全终态（closed/error 且无在途重连） | 红 | 连接断开 |
| 其余（connecting/handshake/部分 down/退避等待） | 黄 | 连接中/重连中/部分不可用 |

健康点只述传输健康；手动重连提示「未决写操作不会自动补发」。

### 3.5 键盘/IME/滚动（v2 原文）
- Enter 发送/Shift+Enter 换行（真 write-composer 本批实现 onKeyDown）；IME composing（keyCode 229）不发送；canSend 才处理+阻止重复；软键盘可见发送钮常驻。
- 列表打开→标题/编辑器合理聚焦；返回→原条目+滚动位置恢复。流式更新仅贴底跟随；向上读旧不拉底。动态视口/安全区下输入/停止/待答可达。

### 3.6 分组与时间（v2 原文+R2-07 兜底）
四互斥组：今天 `[D0,+∞)`；昨天 `[D-1,D0)`；过去 7 天 `[D-7,D-1)`；更早。本地自然日边界；null/无效 Date（无法构造有效时间）→**「更早」单一兜底**。**R1 保证跨午夜/回前台正确刷新分组与相对时间；R2 仅做相对时间呈现格式打磨**。测试冻结时钟测 D0/D-1/D-7 边界+DST+null+无效值。

### 3.7 列表状态不回退（v2 原文）
保留 loading/empty/error/auth-failed/closed、aria-current、同源 resolveTitle、手动刷新、partial/recovery 可发现性；删陈旧文案。

## 5. 施工切批（v2 矩阵保留+R2-07 回滚验法）
